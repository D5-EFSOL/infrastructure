# SelfPortal — развёртывание и мониторинг (инструкция для инженеров)

Общая инструкция по развёртыванию обеих версий портала смены пароля:
**локальной** (`selfportal_local/`) и **доменной** (`selfportal_ad/`).

---

## 1. Какую версию выбрать

| Ситуация | Версия | Каталог |
|---|---|---|
| Сервер **без домена**, меняем пароль **локальных** учётных записей | Локальная | `selfportal_local/` |
| Сервер **в домене AD**, меняем пароль **доменных** учётных записей | Доменная (AD) | `selfportal_AD/` |

Ключевое различие — только в способе смены пароля и проверке административных
групп. Всё остальное (CAPTCHA, блокировки, валидация, заголовки безопасности,
логирование) идентично.

Доменная версия **сама проверяет** членство сервера в домене и завершается
с ошибкой, если сервер не в домене.

---

## 2. Какие файлы нужны

Для развёртывания на сервер шлюза RDP нужно скопировать **три файла** из выбранного
каталога, положив их в одну папку:

| Файл | Назначение |
|---|---|
| `password.aspx` | Страница смены пароля (вся логика) |
| `web.config` | Конфигурация IIS и заголовки безопасности |
| `deploy-selfportal.ps1` | Скрипт развёртывания |

> **Важно про кодировку.** `password.aspx` и `deploy-selfportal.ps1` должны
> оставаться в кодировке **UTF-8 с BOM**. Если скопировать их с потерей BOM
> (например, через некоторые редакторы или средства передачи), Windows
> PowerShell 5.1 и ASP.NET прочитают файл в ANSI-кодировке и кириллица
> «поплывёт». Проверить: первые три байта файла должны быть `EF BB BF`.

---

## 3. Переменные для настройки

Перед запуском откройте `deploy-selfportal.ps1` и задайте значения в начале
скрипта (секция «Параметры»). В обеих версиях набор переменных одинаковый:

| Переменная | Что задаёт | Пример |
|---|---|---|
| `$SiteName` | Имя сайта IIS, к которому привязывается приложение | `"Default Web Site"` |
| `$AppName` | Имя приложения (часть URL-пути) | `"SelfPortal"` |
| `$AppPoolName` | Имя пула приложений IIS | `"SelfPortal"` |
| `$AppPoolUser` | Учётная запись пула | `"NetworkService"` |
| `$TargetDir` | Каталог, куда копируются файлы | `"C:\inetpub\wwwroot\SelfPortal"` |
| `$ClientName` | Имя клиента для итогового URL | `"detpit-as"` |
| `$Port` | Порт, на котором опубликован сайт | `"43445"` |

> `$ClientName` и `$Port` влияют **только на текст итогового URL**, который
> скрипт печатает в конце. Реальную привязку порта и HTTPS-сертификата нужно
> настроить в IIS отдельно (см. раздел 6).

> Обычно менять нужно только `$ClientName` и `$Port`. Остальные значения
> можно оставить по умолчанию.

---

## 4. Как запустить

1. Скопируйте три файла в папку на сервере (например, `C:\SelfPortal\`).
2. Откройте PowerShell **от имени администратора**.
3. Задайте переменные (раздел 3).
4. Выполните:

```powershell
cd C:\SelfPortal
Set-ExecutionPolicy -Scope Process Bypass
.\deploy-selfportal.ps1
```

Скрипт при запуске без прав администратора **сам перезапустит себя с
повышением прав** (через UAC-запрос).

### Что делает скрипт

1. (Только AD-версия) проверяет, что сервер входит в домен.
2. Регистрирует источник `RDWebPassChange` в журнале событий Windows.
3. Создаёт каталог `$TargetDir` и копирует туда `password.aspx` и `web.config`.
4. Создаёт пул приложений `SelfPortal` (NetworkService, .NET 4.0, Integrated).
5. Создаёт приложение `/SelfPortal` на сайте (если существует — пересоздаёт).
6. Перезапускает пул и выводит итоговый URL.

---

## 5. Как проверить результат

1. Откройте в браузере итоговый URL, например:
   `https://<ClientName>.esit.info:<Port>/SelfPortal/`
2. Должна открыться форма «Смена пароля».
3. Проверьте заголовки безопасности (через DevTools → Network или `curl`):
   `Strict-Transport-Security`, `X-Frame-Options`, `Content-Security-Policy`.
4. Попробуйте сменить пароль тестовой учётки:
   - с **неверным** текущим паролем → должно появиться нейтральное сообщение
     и после первой ошибки — CAPTCHA;
   - с **верным** паролем → «Пароль успешно изменён».
5. Проверьте, что события попали в журнал: `eventvwr.msc` → «Журналы Windows»
   → «Приложение», источник `RDWebPassChange`.


## 6. Настройка IIS (выполняется вручную)

Скрипт не настраивает привязку порта и HTTPS-сертификат — это делается в IIS
отдельно:

1. **Привязка порта**: Диспетчер IIS → Сайт → «Привязки» → добавить HTTPS на
   нужном порту.
2. **Сертификат**: назначить действующий TLS-сертификат (например,
   Let's Encrypt) на привязку.
3. **Удалить дефолтный контент IIS**: `iisstart.htm` и каталог
   `C:\inetpub\wwwroot\` — оставить только нужное.
4. **Закрыть лишние приложения** (`/RDWeb` и т.п.), если они не должны быть
   публично доступны.
5. **Рекомендуется**: ограничить доступ к `/SelfPortal` по IP-списку
   (корпоративные подсети) — секция «Ограничения IP-адресов» IIS.

## 7. Настройка мониторинга в Zabbix

Все действия портала пишутся в журнал событий Windows (источник
`RDWebPassChange`). По этим событиям настраиваются оповещения Zabbix.

### 7.1. Получение событий на сервере

Первый способ — **Zabbix agent (active)** с чтением журнала:

1. На сервере включите мониторинг журнала в конфиге Zabbix agent
   (`zabbix_agentd.conf` / `zabbix_agent2.conf`):

   ```
   LogFile=C:\inetpub\logs\zabbix_agentd.log
   ```

   Для чтения событий Windows в Zabbix agent 2 используется ключ
   `eventlog[...]` (см. ниже).

2. Создайте элемент данных (item) типа **Zabbix agent (active)**:

   ```
   Ключ: eventlog[Application,,,,,RDWebPassChange]
   ```

   Ключ читает новые события журнала «Application» с источником
   `RDWebPassChange`.

3. Значение элемента — текст последнего события (сообщение), которое включает
   тип события (`Information`, `Warning`, `Error`) и метаданные (пользователь,
   IP-адрес, причина).

### 7.2. Триггеры

Создайте триггеры на нужные действия (по подстроке в тексте события):

| Событие | Подстрока в сообщении | Уровень |
|---|---|---|
| Перебор пароля | `Неудачная попытка смены пароля` | Warning |
| Успешная смена | `Пароль успешно изменён` | Information |
| Попытка смены пароля администратора | `администра` или `Admin` (в тексте Warning о админ-учётке) | High |
| Блокировка | `заблокирован` / `IP заблокирован` | Warning |

Пример триггера (перебор пароля):

```
find(/SelfPortal/eventlog[Application,,,,,RDWebPassChange],,
     "like","Неудачная попытка смены пароля")=1
```

Пример триггера (попытка смены пароля администратора):

```
find(/SelfPortal/eventlog[Application,,,,,RDWebPassChange],,
     "like","административной учётной записи")=1
```

> Точную подстроку сверьте с текстом реального события в журнале (тексты
> сообщений можно посмотреть в `eventvwr.msc`). IP-адрес, откуда пришёл
> запрос, уже содержится в тексте события.

### 7.3. Альтернативный способ — лог-файл

Если чтение журнала Windows напрямую неудобно, можно пересылать события
в текстовый лог через Windows-механизм «Подписки на события» (Event
Subscriptions / wevtutil) или через внешний агент (например, Winlogbeat),
а затем мониторить этот лог обычным ключом `log[]` Zabbix agent.

### 7.4. Действия (actions)

Привяжите к триггерам действия: отправку в Telegram/email, эскалацию и т.п.
Для события «попытка смены пароля администратора» рекомендуется уровень
критичности **High** с немедленным оповещением дежурного инженера — в тексте
события указан IP-адрес источника.

## 8. Требования к среде

| Компонент | Требование |
|---|---|
| IIS | 7+ (Integrated pipeline), желательно 10+ |
| .NET Framework | 4.0+ (пул приложений `.NET CLR v4.0`) |
| Учётная запись пула | `NetworkService` (задаётся скриптом) |
| Windows | Server (проверено на русскоязычных сборках) |
| Доменная версия | сервер должен входить в домен AD |
| HTTPS | действующий сертификат на привязке порта |
