# SelfPortal — развёртывание (инструкция для инженеров)

Общая инструкция по развёртыванию обеих версий портала смены пароля:
**локальной** (`selfportal_local/`) и **доменной** (`selfportal_ad/`).

---

## 1. Какую версию выбрать

| Ситуация | Версия | Каталог |
|---|---|---|
| Сервер **без домена**, меняем пароль **локальных** учётных записей | Локальная | `selfportal_local/` |
| Сервер **в домене AD**, меняем пароль **доменных** учётных записей | Доменная (AD) | `selfportal_AD/` |

Ключевое различие — способ смены пароля, источник проверки политики сложности
и проверка административных групп. Всё остальное (CAPTCHA, блокировки,
валидация, заголовки безопасности, логирование, интерфейс) идентично.

Доменная версия **сама проверяет** членство сервера в домене и завершается
с ошибкой, если сервер не в домене.

---

## 2. Какие файлы нужны

Для развёртывания на сервер шлюза RDP нужно скопировать **четыре файла** из
выбранного каталога, положив их в одну папку:

| Файл | Назначение |
|---|---|
| `password.aspx` | Страница смены пароля (вся логика) |
| `selfportal.js` | Клиентская логика: «глазок» и динамическая проверка пароля |
| `web.config` | Конфигурация IIS и заголовки безопасности |
| `deploy-selfportal.ps1` | Скрипт развёртывания |

> **Важно про кодировку.** `password.aspx` и `deploy-selfportal.ps1` должны
> оставаться в кодировке **UTF-8 с BOM**. Если скопировать их с потерей BOM
> (например, через некоторые редакторы или средства передачи), Windows
> PowerShell 5.1 и ASP.NET прочитают файл в ANSI-кодировке и кириллица
> «поплывёт». Проверить: первые три байта файла должны быть `EF BB BF`.

---

## 3. Параметры запуска

Параметры задаются аргументами командной строки (необязательны). Остальные
переменные можно оставить по умолчанию — они заданы в начале скрипта.

| Параметр | Что задаёт | По умолчанию |
|---|---|---|
| `-ClientName` | Имя клиента для итогового URL | `client_name` |
| `-Port` | Порт для итогового URL | `port` |

> `-ClientName` и `-Port` влияют **только на текст итогового URL**, который
> скрипт печатает в конце. Реальную привязку порта и HTTPS-сертификата нужно
> настроить в IIS отдельно (см. раздел 6).

---

## 4. Как запустить

1. Скопируйте четыре файла в папку на сервере (например, `C:\SelfPortal\`).
2. Откройте PowerShell **от имени администратора**.
3. Выполните:

```powershell
cd C:\SelfPortal
Set-ExecutionPolicy -Scope Process Bypass
.\deploy-selfportal.ps1 -ClientName detpit-as -Port 43445
```

Скрипт при запуске без прав администратора **сам перезапустит себя с
повышением прав** (через UAC-запрос).

### Что делает скрипт

1. (Только AD-версия) проверяет, что сервер входит в домен.
2. Регистрирует источник `RDWebPassChange` в журнале событий Windows.
3. Создаёт каталог `$TargetDir` и копирует туда `password.aspx`, `selfportal.js`
   и `web.config`.
4. Создаёт пул приложений `SelfPortal` (NetworkService, .NET 4.0, Integrated).
5. **Отключает рециклинг пула** (idle-timeout и periodic restart), чтобы
   счётчики блокировок не сбрасывались раньше их истечения.
6. Создаёт приложение `/SelfPortal` на сайте (если существует — пересоздаёт).
7. Перезапускает пул и выводит итоговый URL.

## 5. Новые возможности интерфейса (v1.1)

- **Подсказка о политике сложности** — перед полем «Новый пароль» выводится
  описание реальной политики сервера («не менее N символов», «символы трёх из
  четырёх категорий»). Источник политики: локальная версия — локальная
  политика SAM, доменная — атрибуты корневого объекта домена.
- **Динамическая проверка** — при наборе нового пароля появляется шкала
  прогресса и чек-лист (длина, заглавные/строчные буквы, цифры, спецсимволы)
  с зелёными галочками.
- **«Глазок»** — кнопка на каждом парольном поле, показывающая вводимые
  символы.

Если политику не удалось прочитать, подсказка и чек-лист просто не выводятся,
а смена пароля не блокируется (реальную проверку всё равно выполнит Windows).

## 6. Как проверить результат

1. Откройте в браузере итоговый URL, например:
   `https://<ClientName>.esit.info:<Port>/SelfPortal/`
2. Должна открыться форма «Смена пароля» с подсказкой о политике сложности.
3. Проверьте заголовки безопасности (через DevTools → Network или `curl`):
   `Strict-Transport-Security`, `X-Frame-Options`, `Content-Security-Policy`.
4. Проверьте «глазок»: символы пароля показываются/скрываются по клику.
5. Начните вводить новый пароль — должна появиться шкала и чек-лист.
6. Попробуйте сменить пароль тестовой учётки:
   - с **неверным** текущим паролем → нейтральное сообщение и после первой
     ошибки — CAPTCHA;
   - с **верным** паролем → «Пароль успешно изменён».
7. Проверьте, что события попали в журнал: `eventvwr.msc` → «Журналы Windows»
   → «Приложение», источник `RDWebPassChange`.

## 7. Настройка IIS (выполняется вручную)

Скрипт не настраивает привязку порта и HTTPS-сертификат — это делается в IIS
отдельно:

1. **Привязка порта**: Диспетчер IIS → Сайт → «Привязки» → добавить HTTPS на
   нужном порту.
2. **Сертификат**: назначить действующий TLS-сертификат (например,
   Let's Encrypt) на привязку.
3. **Удалить дефолтный контент IIS**: `iisstart.htm` и каталог
   `C:\inetpub\wwwroot\` — оставить только нужное.
4. **Закрыть лишние приложения** (`/RDWeb` и т.п.), если они не должны быть
   публично доступны.
5. **Рекомендуется**: ограничить доступ к `/SelfPortal` по IP-списку
   (корпоративные подсети) — секция «Ограничения IP-адресов» IIS.

## 8. Требования к среде

| Компонент | Требование |
|---|---|
| IIS | 7+ (Integrated pipeline), желательно 10+ |
| .NET Framework | 4.0+ (пул приложений `.NET CLR v4.0`) |
| Учётная запись пула | `NetworkService` (задаётся скриптом) |
| Windows | Server (проверено на русскоязычных сборках) |
| Доменная версия | сервер должен входить в домен AD |
| HTTPS | действующий сертификат на привязке порта |
