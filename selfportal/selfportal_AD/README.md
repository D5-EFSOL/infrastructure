# SelfPortal (AD) — портал смены пароля доменного пользователя

Версия портала для **доменных учётных записей** (Active Directory). Отличается
от локальной версии (`../selfportal`) только ядром смены пароля и проверкой
административных групп — вся остальная логика (CAPTCHA, блокировки, валидация,
логирование, заголовки безопасности) идентична.

## Файлы

| Файл | Назначение |
|---|---|
| `password.aspx` | Страница смены пароля доменной учётной записи |
| `web.config` | Заголовки безопасности + Secure cookie + скрытие версий |
| `deploy-selfportal.ps1` | Скрипт развёртывания (с проверкой членства в домене) |
| `README.md` | Этот файл |

> **Кодировка:** `password.aspx` и `deploy-selfportal.ps1` сохранены в
> **UTF-8 с BOM** (обязательно для `powershell.exe` 5.1 и ASP.NET).

## Отличия от локальной версии

### 1. Смена пароля (`ChangeLocalPassword`)

Используется `System.DirectoryServices.AccountManagement` с контекстом
**домена** вместо WinNT-провайдера:

```csharp
using (var ctx = new PrincipalContext(ContextType.Domain))
using (var user = UserPrincipal.FindByIdentity(ctx, IdentityType.SamAccountName, username))
{
    user.ChangePassword(currentPassword, newPassword);
}
```

- `ChangePassword(old, new)` аутентифицирует смену **старым паролем**, поэтому
  работает и для **истёкшего** пароля (в отличие от `SetPassword`, который
  требует прав администратора и не проверяет старый пароль).

### 2. Проверка административных учёток (`IsAdministrator`)

Блокируется смена пароля для членов группы **Domain Admins** (Администраторы
домена). Группа ищется по SID `S-1-5-21-<домен>-512`:

- Доменный SID определяется динамически через
  `System.DirectoryServices.ActiveDirectory.Domain.GetComputerDomain()` →
  `objectSid` домена.
- К доменному SID добавляется фиксированный **RID 512** (RID группы
  Domain Admins).
- Такой подход не зависит от локализации Windows и имени домена.

**Fail closed:** если SID не определён, группа не найдена или возникло
исключение — учётка считается административной и блокируется. Ошибка пишется
в Event Log.

### 3. Валидация имени

Разрешён только `sAMAccountName` (имя без домена). Запрещены `\`, `/`, `@`
(защита от `DOMAIN\user`, `user@domain` и path traversal).

### 4. Развёртывание (`deploy-selfportal.ps1`)

Скрипт **перед развёртыванием проверяет**, что сервер входит в домен
(`Win32_ComputerSystem.PartOfDomain`). Если сервер не в домене — скрипт
завершается с ошибкой и подсказкой использовать локальную версию.

Пул приложений работает под **NetworkService** (машинная учётка, которой
обычно хватает прав на чтение AD и смену пароля доменных пользователей).

## Требования к среде

1. **Сервер должен входить в домен** Active Directory.
2. **Пул приложений** — `NetworkService` (машинная учётка `DOMAIN\SERVER$`).
   Если в домене настроены ограничения на чтение AD для машинных учёток,
   может потребоваться выделенная сервисная учётка.
3. **Права на смену пароля** — `ChangePassword` не требует административных
   прав, достаточно, чтобы учётка пула могла выполнить LDAP-операцию смены
   пароля от имени пользователя (стандартное поведение для машинной учётки).

## Что осталось сделать вручную (не в коде)

1. **Удалить `iisstart.htm`** и дефолтный контент IIS.
2. **Закрыть `/RDWeb`** (RD Web Access), если он не нужен публично.
3. **Ограничить доступ к SelfPortal по IP** (allowlist корпоративных подсетей).
4. **Настроить алерты** на события `RDWebPassChange` (Warning/Error) в Event Log.
5. **Включить HSTS только после** подтверждения, что сайт работает
   исключительно по HTTPS.
6. **Обновить IIS/.NET** — рантайм 4.0.30319 устарел.

## Ограничения текущего решения

- Блокируются только члены **Domain Admins**. Если нужно блокировать также
  `Enterprise Admins`, `Administrators` или свои группы (например, `IT-Admins`) —
  добавьте соответствующие SID в `IsAdministrator`.
- CAPTCHA на `System.Drawing` — простая; для публичного портала лучше
  reCAPTCHA v3 / hCaptcha.
- Смена пароля требует только знание текущего пароля. Для критичных учёток
  можно добавить второй фактор.
